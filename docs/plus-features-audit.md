## How the old compile worked (do not copy the method)

The features were not authored as first-class Frostberg source. A compiled `index.html` was patched:

1. A dedicated module script `id="script-module-plus-needs"` (now `needs.js`).
2. Twee passages/widgets tagged `plusneeds` (now `widgets.twee`).
3. Marker splices into vanilla `minutePassed`, `wearProp`, `initUnderLower`, insecurity type lists, and many location passages.
4. Extra image folders under `img/`.

That marker style is the “sloppy previous integration.” Re-integration should be **plain source edits** at the same semantic hook points (or the official `setup.moddedClothes` array), not HTML/DOM replacement, MutationObservers, or a second `/*plusneeds*/` pass on compiled output.

`needs.js` itself is mostly stateful game logic (tick, consume, accidents, diapers, reputation, flat, renderer helpers). It uses SugarCube `$(document).on(":passagestart")` / `:passagerender` for school lunch, swell notices, and accident wiki inserts. Those event hooks are acceptable; the missing piece is calling the exported functions from vanilla time/prop/clothing init.
